## 2026-11-13 ④ 배차 엔진 구현 해석

- 사용자 승인: 문제지 8.3을 변경하지 않고 결정론적 이동시간, 2027년 비용, 수급 기준 **17,860원**을 적용한다. 17,000×1.025²의 비반올림 값을 별도 기준으로 사용하지 않는다. BM3는 16b의 rain에 따라 12의 속도 0.88배, 14의 공급 0.85배 후 내림, 15의 건당 800원 할증을 적용한다.
- 사용자 승인: 거친 격자 후 상위 후보 주변만 세밀 탐색하며 인스턴스별 한 번의 탐색은 최대 600초이다. 제한에 도달하면 실행 중 후보를 폐기하고 완료된 후보의 최선안을 보존한다. 전역 최소비용/최소인원을 증명하는 방식이 아니다. 규칙→지연→수급→주문당 비용 순이며 같은 비용이면 위탁 접속시간이 적은 안을 선택한다.
- 자정 이후 위탁 상한은 21~24시 값을 연장한다. 실제 이동속도는 구간 출발 시각의 시(hour modulo 24)를 사용한다. 고객 간 이동의 자치구 계수는 출발·도착 고객 자치구의 평균이며 기존 travel_time.py가 계산한다.
- 위탁·피커 계획 변경은 정시의 1시간 단위이다. 같은 번호가 계속 접속하면 하나의 연속 근무구간으로 합치고, 중간에 인원이 줄어 해당 번호가 빠지면 로그아웃한다. 위탁 접속시간은 실제 시간별 접속 인원 합이며 무배송 라이더도 포함한다.
- 23:30 주문 접수 마감 후에도 피킹·배송·복귀를 마친다. 시간제 피커는 마지막 피킹 완료 후 다음 정시, 위탁은 마지막 라이더 복귀 후 다음 정시에 종료하되 24:00 이전으로 자동 조기 종료하지 않는다. 직고용은 지정한 4/8시간 블록 전체를 유급으로 두며 일찍 끝났다고 잘라내지 않는다. 예: 24:08 복귀이면 시간제 위탁은 25:00까지 접속시간에 포함한다.
- 지연 누적 기준 정책도 모든 주문을 배송하도록 시뮬레이션 종료 한도는 48:00이다. 이는 같은 영업일의 잔여 주문 청산이며 다음 영업일 주문을 새로 받는 것은 아니다. 48:00까지 미배송이 남으면 실패 후보로 기록하고 해당 주문을 KPI에서 조용히 제외하지 않는다. 종료 한도와 근방 탐색 시간 범위는 config에 분리한다.
- 거점 외부 대기나 순간 이동은 가정하지 않는다. 모든 근무 라이더는 배송 중이 아니면 거점에서 대기·상차한다. 전 트립의 복귀부터 다음 출발까지, 첫 출발 전, 최종 복귀 후, 배송 0건 근무자의 시간도 bike_bays에 포함한다. 기준 정책/실패 후보가 공간을 넘으면 실행 불가로 기록한다.
- 라이더는 상차 시작부터 거점 복귀까지 한 근무구간에 속해야 한다. 피커는 한 명이 한 주문을 비선점 처리하고, 근무 종료 전 완료 가능한 주문만 접수순으로 시작한다. 인원 축소 시 진행 중 작업을 강제 종료하거나 비용에서 누락하지 않는다.
- T3의 depart_min은 상차 **종료 후 실제 출발**이다. 상차 시작은 depart_min−2이며, 고객 delivered_min은 이동과 아파트 5분/기타 3분 전달을 모두 마친 시각이다. 18:00~20:59 할증은 실제 출발 시각으로 판단한다.
- P0의 최대 3건은 씨앗을 포함한 총 주문 수이다. 고객 간 1.2km는 묶음 내 모든 고객 쌍에 적용하며, 이 직선거리는 P0 묶음 후보 판정에만 쓰고 이동시간을 대체하지 않는다. 모든 정책의 피킹은 FIFO이다. P1/P2는 가장 이른 마감 씨앗에서 시작해 후보를 추가하고, 최근접 방문순서 후 복귀를 포함한 도로거리의 2-opt를 적용한 뒤 모든 전달시각을 재검사한다.
- P1/P2의 W는 씨앗 주문의 피킹 완료부터 센다. 목표 크기 도달, W 만료, 마감 여유 소진 중 먼저 발생한 때 출발한다. 이미 지연이 불가피한 단독 주문도 버리지 않고 배송하며, 후보 추가가 시간창을 깨면 추가하지 않는다.
- 인력 격자 초기치는 시간별 피킹 작업량과 이동시간 기반 작업량 추정으로 만든다. `staffing_intercustomer_min`은 인원 후보 생성용 대리값이며 실제 배차/평가 이동시간에는 쓰이지 않는다. 초기 탐색에서 BM2의 점심 피크를 덮는 블록이 필요해 10시 시작 8시간·17시 시작 8시간 조합을 격자에 포함했다. 배차 중 미래 주문을 미리 묶지는 않는다.
